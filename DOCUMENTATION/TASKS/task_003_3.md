# Task 003-3 — Implement Token Refresh Endpoint

## Parent User Story

[US-003 — Refresh Token Mechanism](../USER_STORIES/user_story_003.md)

## Description

Create a `POST /token/refresh` endpoint that accepts a valid refresh token and returns a new access token, implementing token rotation.

## Work to be Done

1. Create `core/users/routes/token.py` module
2. Implement `POST /token/refresh` route accepting `{"refresh_token": "..."}`
3. Look up the refresh token in the database (hash and compare)
4. Validate: not revoked, not expired
5. If valid:
   - Generate a new access token
   - Generate a new refresh token (rotation)
   - Revoke the old refresh token and set `replaced_by`
   - Store the new refresh token in the database
   - Return both new tokens
6. If the token is revoked but has the same `family_id` as active tokens (reuse detected):
   - Revoke the entire token family
   - Return HTTP 401 (force re-authentication)
7. Register the route in the users blueprint
8. Exempt from CSRF (accepts refresh token instead)

## Expected Outcome

- Users can refresh their access token without re-authenticating
- Token rotation ensures each refresh token is single-use
- Token reuse detection triggers family-wide revocation

## Priority

**High**

## Acceptance Criteria

- [ ] Valid refresh token returns new access + refresh token pair (200)
- [ ] Old refresh token is marked as revoked after use
- [ ] Expired refresh token returns HTTP 401
- [ ] Revoked refresh token returns HTTP 401
- [ ] Token reuse (replaying an already-rotated token) revokes the entire family
- [ ] New refresh token has a fresh expiration time
