# Task 001-2 — Implement Rate Limiting Middleware

## Parent User Story

[US-001 — Rate Limiting on Authentication Endpoints](../USER_STORIES/user_story_001.md)

## Description

Apply rate limiting decorators to the `/signup` and `/login` endpoints with configurable thresholds. The rate limiter should track requests per IP address and return HTTP 429 with a standardized error response when limits are exceeded.

## Work to be Done

1. Apply `@limiter.limit()` decorator to the `signup()` route in `core/users/routes/signup.py`
2. Apply `@limiter.limit()` decorator to the `login()` route in `core/users/routes/login.py`
3. Configure rate limit strings from environment config (e.g., `RATE_LIMIT_LOGIN="5/minute"`, `RATE_LIMIT_SIGNUP="3/minute"`)
4. Implement a custom rate limit exceeded handler returning JSON: `{"error": "Rate limit exceeded", "retry_after": <seconds>}` with HTTP 429
5. Add `Retry-After` header to 429 responses
6. Add rate limit info headers to all responses: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`

## Expected Outcome

- Login and signup endpoints enforce per-IP rate limits
- Exceeding the limit returns HTTP 429 with `Retry-After` header and JSON body
- All responses include rate limit information headers
- Rate limit values are sourced from application configuration

## Priority

**Critical**

## Acceptance Criteria

- [ ] Login endpoint rejects requests exceeding the configured limit with HTTP 429
- [ ] Signup endpoint rejects requests exceeding the configured limit with HTTP 429
- [ ] 429 response includes `Retry-After` header with correct seconds value
- [ ] 429 response body follows the standardized error JSON format
- [ ] Rate limit headers (`X-RateLimit-*`) are present in successful responses
- [ ] Rate limits are tracked per IP address, not globally
