# Task 016-4 — Add Backup Scheduling via Cron or Docker

## Parent User Story

[US-016 — Automated Database Backup Strategy](../USER_STORIES/user_story_016.md)

## Description

Set up automated backup scheduling either via cron (host-based) or a dedicated Docker container.

## Work to be Done

1. Option A — Cron Job:
   - Create `scripts/backup_cron` crontab entry:
     ```cron
     0 2 * * * /app/scripts/db_backup.sh >> /var/log/backup.log 2>&1
     ```
   - Document crontab installation
2. Option B — Docker Backup Container:
   - Create `Docker/backup/Dockerfile` with pg_dump installed
   - Add a backup service to Docker Compose:
     ```yaml
     db-backup:
       build: ./Docker/backup
       environment:
         - BACKUP_SCHEDULE=0 2 * * *
       volumes:
         - backup-data:/backups
     ```
   - Use `supercronic` or similar for in-container scheduling
3. Document both approaches in the project documentation
4. Configure backup notifications (success/failure)

## Expected Outcome

- Backups run automatically on schedule
- Backup results are logged and optionally notified

## Priority

**Low**

## Acceptance Criteria

- [ ] Backups run daily at the configured time
- [ ] Backup results (success/failure) are logged
- [ ] Docker-based approach works with `docker compose up`
- [ ] Backup files are stored on a persistent volume
- [ ] Setup is documented
