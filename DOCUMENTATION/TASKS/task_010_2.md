# Task 010-2 — Create Marshmallow Schemas for All Payloads

## Parent User Story

[US-010 — OpenAPI Specification Auto-Generation](../USER_STORIES/user_story_010.md)

## Description

Define marshmallow schemas for all API request and response payloads to enable automatic OpenAPI spec generation.

## Work to be Done

1. Create `core/schemas/` directory
2. Create schema files:
   - `core/schemas/auth.py` — `LoginSchema`, `SignupSchema`, `LogoutPayloadSchema`
   - `core/schemas/user.py` — `UserResponseSchema`, `UserRoleSchema`
   - `core/schemas/token.py` — `JWTResponseSchema`, `ActivationTokenSchema`
   - `core/schemas/error.py` — `ErrorSchema`, `ValidationErrorSchema`
   - `core/schemas/common.py` — `MessageResponseSchema`, `PaginationSchema`
3. Define fields, validators, and documentation metadata for each schema
4. Map existing WTForms validation rules to marshmallow validators
5. Add examples and descriptions for Swagger display

## Expected Outcome

- All request/response payloads have corresponding marshmallow schemas
- Schemas include validators, descriptions, and examples
- Schema library is reusable across routes

## Priority

**Medium**

## Acceptance Criteria

- [ ] Schemas exist for all API endpoints (signup, login, logout, activation, roles)
- [ ] Schemas include field-level descriptions and examples
- [ ] Validators match the existing business rules
- [ ] Error response schemas are standardized
- [ ] Schemas are importable from `core.schemas`
