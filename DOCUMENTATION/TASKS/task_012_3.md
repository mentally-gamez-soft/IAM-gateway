# Task 012-3 — Create PUT /user/consent Endpoint (Consent Management)

## Parent User Story

[US-012 — GDPR Compliance Endpoints](../USER_STORIES/user_story_012.md)

## Description

Create an endpoint for managing user consent preferences (e.g., marketing emails, analytics, data sharing).

## Work to be Done

1. Create a `UserConsent` model in `core/users/models.py`:
   - `user_id` — FK to `GwUser`
   - `consent_type` — `db.String(50)` (e.g., "marketing", "analytics")
   - `granted` — `db.Boolean`
   - `granted_at` — `db.DateTime`
   - `revoked_at` — `db.DateTime(nullable=True)`
   - `ip_address` — `db.String(45)` for audit
2. In `core/users/routes/gdpr.py`, implement:
   - `GET /user/consent` — returns current consent statuses
   - `PUT /user/consent` — updates consent preferences
3. Create Alembic migration for the `UserConsent` table
4. Log consent changes for compliance audit trail

## Expected Outcome

- Users can view and update their consent preferences
- Consent changes are tracked with timestamps

## Priority

**Medium**

## Acceptance Criteria

- [ ] `GET /user/consent` returns all consent types with status
- [ ] `PUT /user/consent` updates consent preferences
- [ ] Consent changes are timestamped (granted_at / revoked_at)
- [ ] IP address is recorded for audit
- [ ] Consent changes are logged
- [ ] Unauthenticated requests return 401
