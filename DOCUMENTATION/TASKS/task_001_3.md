# Task 001-3 — Add Rate Limit Configuration per Environment

## Parent User Story

[US-001 — Rate Limiting on Authentication Endpoints](../USER_STORIES/user_story_001.md)

## Description

Define rate limit thresholds in each environment configuration file so that development and testing environments have relaxed limits while production has strict limits.

## Work to be Done

1. Add the following variables to `config/default.py`:
   - `RATELIMIT_STORAGE_URI` (Redis URI)
   - `RATE_LIMIT_LOGIN` (e.g., `"5/minute"`)
   - `RATE_LIMIT_SIGNUP` (e.g., `"3/minute"`)
   - `RATE_LIMIT_DEFAULT` (e.g., `"100/hour"`)
   - `RATE_LIMIT_WHITELISTED_IPS` (comma-separated list)
2. Override values in environment-specific configs:
   - `config/local.py`: `"100/minute"` (relaxed)
   - `config/testing.py`: `"1000/minute"` (effectively disabled)
   - `config/dev.py`: `"50/minute"` (moderate)
   - `config/staging.py`: `"10/minute"` (strict)
   - `config/prod.py`: `"5/minute"` (strict)
3. Add corresponding env variables to `.env` template files
4. Add `RATELIMIT_STORAGE_URI` to `validate_config.py` required vars

## Expected Outcome

- Rate limit thresholds are configurable per environment
- Production has strict limits; local/testing have relaxed limits
- Configuration validation catches missing rate limit settings at startup

## Priority

**High**

## Acceptance Criteria

- [ ] Rate limit variables are defined in `config/default.py` with sensible defaults
- [ ] Each environment config overrides rate limits appropriately
- [ ] `.env` template files include the new variables
- [ ] `validate_config.py` validates the presence of rate limit configuration
- [ ] Changing an env variable changes the effective rate limit without code changes
