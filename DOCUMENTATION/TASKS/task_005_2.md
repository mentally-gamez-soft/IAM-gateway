# Task 005-2 — Implement /ready Readiness Endpoint with Dependency Checks

## Parent User Story

[US-005 — Health Check and Readiness Probes](../USER_STORIES/user_story_005.md)

## Description

Create a `GET /ready` readiness endpoint that verifies database connectivity and external service availability before reporting the application as ready to serve traffic.

## Work to be Done

1. Add `GET /ready` route to `core/users/routes/health.py`
2. Implement dependency checks:
   - **Database**: Execute `SELECT 1` via SQLAlchemy with a 3-second timeout
   - **External Password Scoring API**: HTTP HEAD/GET to the configured URL with a 3-second timeout
   - **SMTP Server**: Attempt connection to `EMAIL_SERVER:EMAIL_PORT` with a 3-second timeout (only if `APP_SEND_EMAILS=True`)
3. Return response:
   - All checks pass: `{"status": "ready", "checks": {"database": "ok", "password_api": "ok", "smtp": "ok"}}` — HTTP 200
   - Any critical check fails: `{"status": "not_ready", "checks": {...}}` — HTTP 503
4. Each check reports: `"ok"`, `"error"`, or `"skipped"` with optional `detail` field
5. Total endpoint timeout: 5 seconds maximum

## Expected Outcome

- `/ready` endpoint accurately reflects system readiness
- Failed dependencies return 503, preventing traffic routing to unhealthy instances
- Each dependency check has an independent timeout

## Priority

**High**

## Acceptance Criteria

- [ ] `GET /ready` returns 200 when all dependencies are available
- [ ] `GET /ready` returns 503 when the database is unreachable
- [ ] Each check has an individual timeout (3 seconds max)
- [ ] Total response time does not exceed 5 seconds
- [ ] Check results include individual status and optional error details
- [ ] Optional services (SMTP) do not cause failure when disabled in config
