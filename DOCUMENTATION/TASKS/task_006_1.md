# Task 006-1 — Restructure Blueprint with Versioned URL Prefix

## Parent User Story

[US-006 — API Versioning Strategy](../USER_STORIES/user_story_006.md)

## Description

Refactor the Flask Blueprint registration to use a consistent versioned URL prefix (`/api/v1`) for all API endpoints, eliminating the current dynamic `/<app>/api/<version>/` pattern.

## Work to be Done

1. Update `core/users/__init__.py` to register the blueprint with `url_prefix="/api/v1"`
2. Remove the dynamically constructed route prefixes from each route file:
   - Remove `API_TITLE`, `API_PREFIX`, `API_VERSION`, `BASE_ROUTE` variables from `signup.py`, `login.py`, `logout.py`, `email_activation.py`, `sanity_check.py`, `roles.py`
   - Remove the duplicated versioned `@users_bp.route()` decorators (keep only the short route like `/signup`)
3. Update the sanity check default route from `/` to be served by a separate root blueprint or redirect
4. Ensure all routes are accessible under `/api/v1/...`
5. Verify that the Swagger UI route (`/swagger`) remains at the top level (not versioned)

## Expected Outcome

- All API routes are accessible under `/api/v1/` prefix
- No more duplicated route registrations
- Clean, maintainable route definitions

## Priority

**High**

## Acceptance Criteria

- [ ] All API routes are accessible under `/api/v1/<endpoint>` pattern
- [ ] Dynamic `API_TITLE`/`API_PREFIX`/`API_VERSION`/`BASE_ROUTE` variables are removed from route files
- [ ] No duplicate route decorators exist
- [ ] Swagger UI remains accessible at `/swagger`
- [ ] Application starts without route conflicts
- [ ] Health endpoints remain at root level (`/health`, `/ready`) if implemented
