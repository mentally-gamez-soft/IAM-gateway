# Task 003-4 — Update Login/Logout Routes for Dual-Token Flow

## Parent User Story

[US-003 — Refresh Token Mechanism](../USER_STORIES/user_story_003.md)

## Description

Update the login and logout routes to issue and revoke both access and refresh tokens.

## Work to be Done

1. Update `core/users/routes/login.py`:
   - After successful authentication, call `generate_token_pair()` instead of `initiate_session_jwt()`
   - Return both `access_token` and `refresh_token` in the response body
   - Store the refresh token hash in the database via `RefreshToken.create()`
   - Keep `jwt_session_id` updated with the access token for backward compatibility
2. Update `core/users/routes/logout.py`:
   - Revoke all refresh tokens for the user (`RefreshToken.revoke_all_for_user()`)
   - Clear `jwt_session_id`
3. Update response schemas to include both tokens
4. Ensure the authorization guard still works with the short-lived access token

## Expected Outcome

- Login returns both access and refresh tokens
- Logout invalidates all tokens for the user
- Existing authorization decorators continue to work

## Priority

**High**

## Acceptance Criteria

- [ ] Login response includes both `access_token` and `refresh_token`
- [ ] Refresh token is stored in the database upon login
- [ ] Logout revokes all refresh tokens for the user
- [ ] Authorization guard works with the new access token format
- [ ] Existing tests updated to handle dual-token response
