# Task 002-1 — Add Password Reset Token Field to GwUser Model

## Parent User Story

[US-002 — Password Reset / Forgot Password Flow](../USER_STORIES/user_story_002.md)

## Description

Add a new field `last_password_reset_token` to the `GwUser` model to store the most recent password reset token and prevent token reuse. Create the corresponding database migration.

## Work to be Done

1. Add `last_password_reset_token = db.Column(db.String(200), unique=False, nullable=True)` to the `GwUser` model in `core/users/models.py`
2. Add a `password_reset_requested_on = db.Column(db.DateTime, nullable=True)` field to track when the reset was requested
3. Add a helper method `GwUser.set_password_reset_token(token)` that stores the token and timestamp
4. Add a helper method `GwUser.clear_password_reset_token()` that nullifies the token fields
5. Generate a new Alembic migration: `flask --app application db migrate -m "add_password_reset_fields"`
6. Test the migration with `flask --app application db upgrade` and `flask --app application db downgrade`

## Expected Outcome

- `GwUser` model has `last_password_reset_token` and `password_reset_requested_on` fields
- Migration file created and tested (up and down)
- Helper methods available for setting and clearing the reset token

## Priority

**Critical**

## Acceptance Criteria

- [ ] New fields are present on the `GwUser` model
- [ ] Alembic migration file is generated and applies cleanly
- [ ] Downgrade migration removes the new fields without data loss in other columns
- [ ] Helper methods `set_password_reset_token` and `clear_password_reset_token` work correctly
- [ ] Existing tests still pass after the migration
