# Task 002-2 — Implement Forgot-Password Endpoint

## Parent User Story

[US-002 — Password Reset / Forgot Password Flow](../USER_STORIES/user_story_002.md)

## Description

Create a `POST /forgot-password` endpoint that accepts an email address, generates a time-limited password reset token, and triggers the sending of a reset email. The endpoint must always return HTTP 200 regardless of whether the email exists (to prevent email enumeration attacks).

## Work to be Done

1. Create `core/users/routes/password_reset.py` module
2. Implement `POST /forgot-password` route accepting `{"email": "..."}` JSON body
3. Look up the user by email; if found:
   - Generate a time-limited token using `itsdangerous.URLSafeTimedSerializer` (reuse logic from `validation_token.py`)
   - Store the token in `GwUser.last_password_reset_token`
   - Send a password reset email (delegate to mail service)
4. Always return `{"message": "If the email exists, a reset link has been sent.", "status": 200}` (prevent enumeration)
5. Register the new route in the users blueprint
6. Exempt this endpoint from CSRF protection (it's a public endpoint)
7. Add the `@count_api_calls` decorator for statistics tracking

## Expected Outcome

- `POST /forgot-password` endpoint is functional and registered
- A valid reset token is generated and stored for existing users
- The endpoint never reveals whether an email exists in the system
- The reset email is sent (or queued) upon valid request

## Priority

**Critical**

## Acceptance Criteria

- [ ] Endpoint returns 200 for both existing and non-existing emails
- [ ] Response body is identical for existing and non-existing emails
- [ ] Token is generated using `URLSafeTimedSerializer` with the application secret key
- [ ] Token is stored in the user's `last_password_reset_token` field
- [ ] Email sending is triggered for valid email addresses
- [ ] Endpoint is tracked by the API statistics decorator
- [ ] Endpoint does not require authentication
