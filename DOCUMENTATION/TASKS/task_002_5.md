# Task 002-5 — Write Tests for the Password Reset Flow

## Parent User Story

[US-002 — Password Reset / Forgot Password Flow](../USER_STORIES/user_story_002.md)

## Description

Create a comprehensive test suite for the entire password reset flow covering all success and error scenarios.

## Work to be Done

1. Create `tests/test_password_reset.py` with the following test cases:
   - Forgot password with valid existing email sends email and returns 200
   - Forgot password with non-existing email returns 200 (no email sent)
   - Reset password with valid token and valid password succeeds (200)
   - Reset password with expired token returns 422
   - Reset password with invalid/tampered token returns 422
   - Reset password with already-used token returns 422
   - Reset password with weak password returns 422
   - JWT session is invalidated after successful password reset
   - User can log in with new password after reset
   - User cannot log in with old password after reset
2. Mock the email sending to avoid actual SMTP calls in tests
3. Use the testing configuration (CSRF disabled)

## Expected Outcome

- Full test coverage for the password reset flow
- Tests validate both happy paths and error scenarios
- Tests run without external dependencies (mocked email)

## Priority

**High**

## Acceptance Criteria

- [ ] At least 10 test cases covering the scenarios above
- [ ] All tests pass in the CI pipeline
- [ ] Email sending is mocked (no actual emails sent during testing)
- [ ] Test coverage for `password_reset.py` exceeds 90%
- [ ] Tests verify database state changes (token storage, password hash update, session invalidation)
