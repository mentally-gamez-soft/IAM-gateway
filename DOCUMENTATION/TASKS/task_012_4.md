# Task 012-4 — Block Deleted Users from Login

## Parent User Story

[US-012 — GDPR Compliance Endpoints](../USER_STORIES/user_story_012.md)

## Description

Ensure that soft-deleted users cannot log in or interact with the API.

## Work to be Done

1. In `core/users/routes/login.py`, add a check for `is_deleted` flag:
   - Before validating credentials, check if `user.is_deleted is True`
   - Return a generic error message (do not reveal that the account was deleted)
2. In `core/auth/auth_guard.py`, add `is_deleted` check to the authorization guard
3. In Flask-Login's user loader, return `None` for deleted users
4. Ensure activation tokens for deleted users are rejected
5. Verify that middleware and guards handle the deleted state

## Expected Outcome

- Deleted users cannot authenticate or access any endpoint
- No information leakage about account deletion status

## Priority

**High**

## Acceptance Criteria

- [ ] Soft-deleted users receive login denied (generic error message)
- [ ] Active sessions of deleted users are rejected by guards
- [ ] No leakage of deletion status in error messages
- [ ] User loader returns `None` for deleted users
- [ ] Email activation for deleted users fails gracefully
