# Task 002-3 — Implement Reset-Password Endpoint

## Parent User Story

[US-002 — Password Reset / Forgot Password Flow](../USER_STORIES/user_story_002.md)

## Description

Create a `POST /reset-password/<token>` endpoint that validates the reset token, applies the new password (with full validation), invalidates all JWT sessions, and requires the user to log in again.

## Work to be Done

1. Add `POST /reset-password/<token>` route to `core/users/routes/password_reset.py`
2. Deserialize the token using `URLSafeTimedSerializer` with configurable expiration (default 30 minutes)
3. Extract the email from the token and look up the user
4. Verify the token matches `GwUser.last_password_reset_token` (prevent reuse)
5. Validate the new password using existing `PasswordValidator` (scoring API + rules)
6. Update the password hash via `GwUser.set_password(new_password)`
7. Clear `jwt_session_id` (invalidate current session)
8. Clear `last_password_reset_token` (prevent token reuse)
9. Return success response with instruction to log in again
10. Handle error cases: expired token, invalid token, token already used, password validation failure

## Expected Outcome

- Password is reset securely with full validation
- All existing sessions are invalidated
- Token cannot be reused after successful reset
- Expired or invalid tokens return appropriate error responses

## Priority

**Critical**

## Acceptance Criteria

- [ ] Valid token + valid password results in password update and HTTP 200
- [ ] Expired token returns HTTP 422 with "Token expired" message
- [ ] Invalid/tampered token returns HTTP 422 with "Invalid token" message
- [ ] Already-used token returns HTTP 422 with "Token already used" message
- [ ] Weak password (failing validation) returns HTTP 422 with validation details
- [ ] `jwt_session_id` is cleared after successful reset
- [ ] `last_password_reset_token` is cleared after successful reset
- [ ] User must log in again after password reset
