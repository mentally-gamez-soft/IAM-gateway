# Task 017-6 — Configure CI Pipeline for Test Execution and Coverage

## Parent User Story

[US-017 — Integration and End-to-End Test Suite](../USER_STORIES/user_story_017.md)

## Description

Configure the CI pipeline to run the full test suite with coverage reporting and set minimum coverage thresholds.

## Work to be Done

1. Update CI configuration (GitHub Actions, GitLab CI, or equivalent):
   - Set up PostgreSQL service container for integration tests
   - Install Python dependencies
   - Run pytest with coverage: `pytest --cov=core --cov-report=xml --cov-report=term`
   - Upload coverage report as artifact
2. Add coverage thresholds to `pyproject.toml`:
   ```toml
   [tool.pytest.ini_options]
   minversion = "8.0"
   testpaths = ["tests"]
   
   [tool.coverage.run]
   source = ["core", "server"]
   
   [tool.coverage.report]
   fail_under = 80
   ```
3. Add test stages: unit → integration → security
4. Configure test parallelization if beneficial
5. Add badge for coverage status (optional)

## Expected Outcome

- Tests run automatically in CI on every push/PR
- Coverage is tracked and enforced
- Test failures block merges

## Priority

**Medium**

## Acceptance Criteria

- [ ] CI runs the full test suite successfully
- [ ] Coverage report is generated and archived
- [ ] Minimum coverage threshold (80%) is enforced
- [ ] Test failures cause the CI pipeline to fail
- [ ] PostgreSQL service is available for integration tests
- [ ] Test execution time is reasonable (<5 minutes)
