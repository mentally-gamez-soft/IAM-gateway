# Task 003-2 — Update JWT Handler for Dual-Token Generation

## Parent User Story

[US-003 — Refresh Token Mechanism](../USER_STORIES/user_story_003.md)

## Description

Modify the JWT handler to generate both a short-lived access token and a long-lived refresh token, with configurable lifetimes.

## Work to be Done

1. Update `core/auth/jwt/jwt_handler.py`:
   - Rename `initiate_session_jwt` to `generate_access_token` (or keep backward compatible)
   - Add `generate_refresh_token(user_id)` function
   - Add `generate_token_pair(payload)` function that returns both tokens
2. Access token lifetime: 15 minutes (configurable via `JWT_ACCESS_TOKEN_LIFETIME`)
3. Refresh token: generate a secure random string (not a JWT), hash before storage
4. Add configuration variables to `config/default.py`:
   - `JWT_ACCESS_TOKEN_LIFETIME` (default: 15 minutes)
   - `JWT_REFRESH_TOKEN_LIFETIME` (default: 7 days)
5. Ensure backward compatibility with existing code using `initiate_session_jwt`

## Expected Outcome

- Both access and refresh tokens are generated from a single call
- Access token has a short lifetime; refresh token has a long lifetime
- Configuration is externalized via environment variables

## Priority

**High**

## Acceptance Criteria

- [ ] `generate_token_pair()` returns `{"access_token": "...", "refresh_token": "..."}`
- [ ] Access token expires after the configured short lifetime
- [ ] Refresh token is a secure random string (at least 64 characters)
- [ ] Refresh token is hashed (SHA-256) before database storage
- [ ] Existing `initiate_session_jwt` still works (backward compatible)
- [ ] Token lifetimes are configurable per environment
