# Task 010-3 — Annotate Route Endpoints with Schema Decorators

## Parent User Story

[US-010 — OpenAPI Specification Auto-Generation](../USER_STORIES/user_story_010.md)

## Description

Add `flask-smorest` Blueprint and schema decorators to each route endpoint so that the OpenAPI specification is auto-generated from code.

## Work to be Done

1. Convert routes to use `flask-smorest` `Blueprint` instead of standard Flask `Blueprint`
2. Add `@blp.arguments(Schema)` decorators for request body validation
3. Add `@blp.response(200, Schema)` decorators for response documentation
4. Add `@blp.alt_response(4xx, Schema)` for error responses
5. Update each route file: `signup.py`, `login.py`, `logout.py`, `email_activation.py`, `roles.py`, `sanity_check.py`
6. Ensure decorators coexist with existing security decorators (`authorization_guard`, `login_required`, etc.)
7. Verify decorator ordering does not break existing functionality

## Expected Outcome

- All routes are annotated with schema decorators
- OpenAPI spec is auto-generated with correct paths, methods, and schemas
- Existing security decorators continue to work

## Priority

**Medium**

## Acceptance Criteria

- [ ] Each route has request and response schema decorators
- [ ] OpenAPI spec includes all endpoints with correct schemas
- [ ] Security decorators (guards, login_required) still function correctly
- [ ] Request validation via marshmallow works alongside WTForms validation
- [ ] No behavioral changes to existing endpoints
