# Task 003-5 — Add Token Family Tracking and Reuse Detection

## Parent User Story

[US-003 — Refresh Token Mechanism](../USER_STORIES/user_story_003.md)

## Description

Implement token family tracking to detect refresh token reuse, which indicates potential token theft. When reuse is detected, all tokens in the family must be revoked, forcing the user to re-authenticate.

## Work to be Done

1. Assign a `family_id` (UUID) to each refresh token at login time
2. On token refresh, the new refresh token inherits the same `family_id`
3. When a refresh token that has already been rotated is reused:
   - Query all tokens with the same `family_id`
   - Mark all as revoked (`revoked=True`, `revoked_on=now()`)
   - Log a security warning with user ID and IP address
4. Add a `detect_reuse(token_hash)` method to the `RefreshToken` model
5. Consider adding an alert mechanism (email to admin or webhook)

## Expected Outcome

- Token theft is detectable via family-based reuse tracking
- All tokens in a compromised family are immediately revoked
- Security events are logged for audit purposes

## Priority

**Medium**

## Acceptance Criteria

- [ ] Each login session creates a unique `family_id`
- [ ] Refreshed tokens inherit the parent's `family_id`
- [ ] Replaying an already-used refresh token revokes the entire family
- [ ] A security warning is logged with relevant details (user ID, IP, timestamp)
- [ ] After family revocation, the user must log in again
