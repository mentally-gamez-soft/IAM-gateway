# Task 009-2 — Add Environment-Specific CORS Origins Configuration

## Parent User Story

[US-009 — CORS Configuration](../USER_STORIES/user_story_009.md)

## Description

Configure allowed CORS origins per environment, with permissive settings in development and strict whitelisting in production.

## Work to be Done

1. Add `CORS_ORIGINS` to each environment config:
   - `config/local.py`: `CORS_ORIGINS = "*"` (allow all origins)
   - `config/testing.py`: `CORS_ORIGINS = "*"` (allow all for tests)
   - `config/dev.py`: `CORS_ORIGINS = "*"` (allow all for development)
   - `config/staging.py`: `CORS_ORIGINS = ["https://staging.example.com"]`
   - `config/prod.py`: `CORS_ORIGINS = ["https://app.example.com"]`
2. Add `CORS_ORIGINS` to `.env` files as a comma-separated string
3. Add parsing logic in `config/default.py` to convert the comma-separated string to a list
4. Add `CORS_ORIGINS` to the config validation in `validate_config.py`

## Expected Outcome

- Production allows only whitelisted origins
- Development allows all origins for convenience
- Origins are configurable via environment variables

## Priority

**Medium**

## Acceptance Criteria

- [ ] Production config restricts origins to specific domains
- [ ] Dev/local configs allow all origins
- [ ] Origins are configurable via `.env` files
- [ ] Requests from unauthorized origins are rejected in production settings
- [ ] Configuration validation catches missing CORS settings
