# Task 003-6 — Write Tests for Refresh Token Lifecycle

## Parent User Story

[US-003 — Refresh Token Mechanism](../USER_STORIES/user_story_003.md)

## Description

Create a comprehensive test suite covering the entire refresh token lifecycle: issuance, refresh, rotation, expiration, revocation, and reuse detection.

## Work to be Done

1. Create `tests/test_refresh_token.py` with test cases:
   - Login returns both access and refresh tokens
   - Valid refresh token returns new token pair (200)
   - Old refresh token is revoked after rotation
   - Expired refresh token returns 401
   - Revoked refresh token returns 401
   - Token reuse (replaying rotated token) revokes entire family
   - Logout revokes all refresh tokens for the user
   - Access token with short lifetime expires correctly
   - New access token works after refresh
   - Multiple concurrent sessions generate independent token families
2. Test the `RefreshToken` model methods independently
3. Test edge cases: concurrent refresh attempts, rapid successive refreshes

## Expected Outcome

- Complete test coverage for the refresh token feature
- Edge cases and security scenarios validated
- Tests are independent and repeatable

## Priority

**Medium**

## Acceptance Criteria

- [ ] At least 12 test cases covering the scenarios above
- [ ] All tests pass in the CI pipeline
- [ ] Token reuse detection is verified via tests
- [ ] Test coverage for token-related modules exceeds 90%
- [ ] Tests do not depend on specific timing (use mocked time where needed)
