# Task 001-4 — Write Unit and Integration Tests for Rate Limiting

## Parent User Story

[US-001 — Rate Limiting on Authentication Endpoints](../USER_STORIES/user_story_001.md)

## Description

Create a comprehensive test suite validating that rate limiting works correctly on the signup and login endpoints, including positive cases (within limits) and negative cases (exceeding limits).

## Work to be Done

1. Create `tests/test_rate_limiting.py` with the following test cases:
   - Login request within rate limit succeeds (200)
   - Login request exceeding rate limit returns 429
   - Signup request within rate limit succeeds (200)
   - Signup request exceeding rate limit returns 429
   - 429 response includes `Retry-After` header
   - 429 response body matches expected JSON format
   - Rate limit headers are present in successful responses
   - Rate limits reset after the configured window
   - Different IP addresses have independent rate counters
2. Use the testing configuration with high limits to avoid interference with existing tests
3. Mock or use an in-memory storage backend for unit tests

## Expected Outcome

- All rate limiting behaviors are covered by automated tests
- Tests run reliably in CI without requiring a Redis instance (for unit tests)
- Test isolation: rate limiting tests do not interfere with other test suites

## Priority

**High**

## Acceptance Criteria

- [ ] At least 8 test cases covering the scenarios listed above
- [ ] Tests pass with both in-memory and Redis backends
- [ ] No existing tests are broken
- [ ] Test coverage for the rate limiting module exceeds 90%
- [ ] Tests are grouped/tagged for selective execution
