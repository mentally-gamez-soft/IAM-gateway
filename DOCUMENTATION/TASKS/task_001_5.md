# Task 001-5 — Update Docker Compose with Redis Service

## Parent User Story

[US-001 — Rate Limiting on Authentication Endpoints](../USER_STORIES/user_story_001.md)

## Description

Add a Redis container to both the development and production Docker Compose configurations so that rate limiting state is persisted across application restarts and shared across Gunicorn workers.

## Work to be Done

1. Add a `redis` service to `Docker/application/dev/docker-compose-dev.yaml`:
   - Image: `redis:7-alpine`
   - Port mapping: `6379:6379` (dev only)
   - Volume for data persistence
2. Add a `redis` service to `Docker/application/prod/docker-compose-prod.yaml`:
   - Image: `redis:7-alpine`
   - No external port exposure (internal network only)
   - Volume for data persistence
   - `maxmemory` policy configured for cache eviction
3. Connect Redis to the `app_bridge` network in production
4. Update `.env` files with `RATELIMIT_STORAGE_URI=redis://redis:6379/0`
5. Add `depends_on: redis` to the application service
6. Update `docker_manager.sh` if needed to handle the new service

## Expected Outcome

- Redis is available as part of the Docker stack in both dev and prod environments
- The application connects to Redis for rate limit state storage
- Redis data persists across container restarts

## Priority

**High**

## Acceptance Criteria

- [ ] `docker compose up` starts Redis alongside the application
- [ ] Application successfully connects to Redis for rate limiting
- [ ] Redis is not exposed externally in the production configuration
- [ ] Redis data persists via a named Docker volume
- [ ] Stopping and restarting the stack preserves rate limit counters
