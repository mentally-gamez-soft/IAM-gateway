# Task 012-2 — Create DELETE /user/account Endpoint (Right to Erasure)

## Parent User Story

[US-012 — GDPR Compliance Endpoints](../USER_STORIES/user_story_012.md)

## Description

Create an authenticated endpoint that allows users to request the deletion of their account and all associated data.

## Work to be Done

1. In `core/users/routes/gdpr.py`, implement `DELETE /user/account`:
   - Require authentication via `@login_required` and `authorization_guard`
   - Require confirmation (e.g., `{"confirm": true, "password": "..."}`)
   - Validate the user's password before proceeding
   - Perform cascading soft-delete or hard-delete:
     - Add `is_deleted` flag and `deleted_at` timestamp to `GwUser`
     - Revoke all active sessions/tokens
     - Anonymize or delete related records
   - Return a confirmation response
2. Add model fields: `is_deleted`, `deleted_at` to `GwUser`
3. Create Alembic migration for new fields
4. Log the deletion request for audit and compliance

## Expected Outcome

- Users can request account deletion
- Account is soft-deleted with audit trail
- All active sessions are terminated

## Priority

**High**

## Acceptance Criteria

- [ ] `DELETE /user/account` soft-deletes the user account
- [ ] Password confirmation is required
- [ ] Active sessions/tokens are revoked
- [ ] `is_deleted` flag and `deleted_at` timestamp are set
- [ ] Deleted users cannot log in
- [ ] Deletion request is logged for audit
- [ ] Unauthenticated requests return 401
